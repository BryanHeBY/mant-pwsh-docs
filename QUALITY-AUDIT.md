# Documentation quality audit

This record tracks the repository-wide deep review beyond the existing
`reviewed` status in the upstream catalogs. The authoritative list of 416
published documents remains `release/v0.7.0.json`; this file does not duplicate
that inventory.

## Quality gates

A deep-reviewed document must satisfy all applicable gates:

1. **Structure:** portable validation, ManT parsing, links, source registration,
   and semantic entries pass.
2. **Primary sources:** material claims agree with the locked official source;
   current behavior is rechecked when version drift is plausible.
3. **Version and platform boundaries:** PowerShell edition, operating system,
   installed feature, privilege, locale, and tool-version differences are
   explicit.
4. **Safety:** examples state their scope and avoid destructive, privileged,
   remote, persistent, or privacy-sensitive actions unless the consequence and
   safer inspection path are clear.
5. **Runtime evidence:** safe claims are exercised on applicable hosts; unsafe
   operations use help, discovery, fixtures, or explicit pending evidence
   instead of production mutation.
6. **Human usability:** TLDR examples, explanations, errors, outputs, and common
   mistakes are concise and sufficient to make a correct decision.
7. **Agent usability:** important options or subcommands are addressable,
   likely troubleshooting terms are searchable, and ManT can return a bounded
   node without requiring the full document.

The catalog term `reviewed` continues to mean editorial, provenance,
ManT-parse, and locked-upstream accessibility review. The stronger catalog term
`verified` still requires recorded runtime verification on every platform
declared by that document. Deep review uses the gates above and does not silently
change either catalog definition.

## Evidence classes

| Class | Meaning | Typical record |
| --- | --- | --- |
| Static | Repository and ManT validators passed | `npm run validate`, content and syntax audits |
| Source | Claim checked against a primary official source | Per-document source and locked baseline in `upstream/` |
| Runtime | Behavior observed on a named host/version | `release/v0.7.0-runtime-evidence.md` |
| Consumer | ManT CLI or MCP found the intended bounded content | Direct-file query during editing or installed-source query after commit |

Live MCP responses and copied upstream prose are not committed. Durable records
contain the query, environment, conclusion, and relevant document location.

## Review order

| Batch | Scope | State | Reason for priority |
| --- | --- | --- | --- |
| 1 | Windows PowerShell 5.1, 30 pages | editorial/source/metadata pass complete; remaining specialized runtime fixtures recorded separately | Available on the current Windows host; quoting, encoding, aliases, and native boundaries are high-risk |
| 2 | PowerShell 7, 30 pages | editorial/source/metadata pass complete; Windows/Linux evidence exists, macOS and remaining platform fixtures pending | Cross-version differences affect most Agent-authored commands |
| 3 | Windows tools with destructive, privileged, remote, security, storage, boot, service, task, or identity behavior | deep review complete; unsafe operations retain explicit fixture boundaries | Highest consequence if an example is misunderstood |
| 4 | Remaining Windows tools | in progress | Broadest inventory and greatest version/edition availability variation |
| 5 | Cross-platform tools, 6 pages | in progress; Windows/Linux implementation evidence exists, macOS and compatible dotnet SDK hosts pending | Small set, but executable/version differences span three operating systems |

Within each batch, review the shell boundary, side effects, version drift, and
Agent failure modes before editorial polish. A batch is complete only when every
document in its release inventory has an evidence-backed disposition.

## ManT consumer observations

These are workflow notes, not blockers for the documentation audit:

- ManT 0.7.0 validates all 416 files and can address semantic entries and
  search matches through the CLI and MCP server.
- Configured Git-backed sources refresh by committed revision. A dirty local
  worktree therefore remains `unchanged`; use `mant --input FILE`
  to validate drafts, then test the configured source after commit.
- In the current Codex client, some optional MCP enum inputs are displayed as
  untyped values even though valid string enum values work. Treat this as a
  client/schema-integration observation unless a server-side reproducer proves
  otherwise.
- ManT 0.7.0 preserves non-empty dotted dash-option segments. CertUtil's exact
  `-ca.cert` and `-ca.chain` entries are option-role selectors, and direct
  explanations return one unambiguous selection for each.
- For catalog-scoped upstream maintenance, invoke
  `node tools/verify-upstream.mjs --catalog pwsh7` directly. `npm run ... --
  --catalog pwsh7` is not equivalent because npm treats `--catalog` as its own
  configuration option and forwards only the value.
- ManT 0.7.0 normalizes Klist's positional `?` help command and the `/?`/`-?`
  option spellings to the same selector. Declaring both command- and
  option-role entries makes `--explain=?` ambiguous. Keep one semantic help
  entry and describe the additional installed spelling in its prose.
- A Windows sleep/resume cycle can leave a long-lived Codex MCP stdio handle
  closed even though a newly started ManT 0.6.1 MCP server is healthy. Require
  a valid response before recording latency, and restart the MCP connection
  after `Transport closed`. A still-running, apparently responsive ManT child
  is not sufficient evidence that its stdio connection is usable; this
  observation does not by itself prove that ManT closed the pipe.

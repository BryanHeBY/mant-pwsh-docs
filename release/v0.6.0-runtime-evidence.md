## Windows service and process help drift — 2026-08-12

Read-only local help and query probes on Windows NT `10.0.26200.0` found two
interfaces where generated help assumptions or the current online reference
are insufficient:

- Bare `sc.exe` and `sc.exe /?` printed roughly 90 help lines but returned
  1639 (`ERROR_INVALID_COMMAND_LINE`). `sc.exe config` without a service
  printed usage with the same code, while `sc.exe query` without a service
  enumerated services. `query /?` and `qmanagedaccount /?` treated `/?` as a
  service name and returned 123. Therefore neither “append `/?`” nor “omit the
  operand” is a uniform SC help protocol.
- Installed SC help exposed `qpreferrednode`, `qmanagedaccount`,
  `qprotection`, `quserservice`, `preferrednode`, and `managedaccount` beyond
  the page's former semantic inventory. Querying EventLog with
  `qmanagedaccount`, `qprotection`, `qsidtype`, and `qprivs` succeeded;
  `qpreferrednode` returned 87 because that service has no applicable value.
  No service control or configuration command was sent.
- Installed `tasklist.exe /?` exposed `/APPS`; `tasklist.exe /apps /fo csv`
  returned 41 lines, a `Package Name` column, and exit code 0. Microsoft's
  current online Tasklist syntax omits `/APPS`, so the repository treats it as
  installed-help/build-dependent and release verification gates it on local
  help. No process contents are retained in this evidence.

The SC and Tasklist pages now expose these boundaries through semantic entries,
named mistakes, version notes, and ManT-addressable text.

SchTasks help review found another omitted top-level operation: `/ShowSid`.
`schtasks.exe /showsid /tn '\Microsoft\Windows\Defrag\ScheduledDefrag'`
returned one SID-bearing line and exit code 0 without running or changing the
task. The page now distinguishes that dedicated task SID from the action's
run-as principal. PowerShell 7.6.4 metadata also confirmed that
`Get-ScheduledTaskInfo -InputObject` accepts pipeline input, and the documented
`Get-ScheduledTask | Get-ScheduledTaskInfo` shape returned one result for the
same built-in task.

RegIni usage review found that the page's former `-?` semantic option and
kernel-path-only statement did not match the installed parser. Bare
`regini.exe` and `regini.exe /?` produced 153 rendered lines after Windows
PowerShell native-error wrapping/stream merging and returned exit code 1; no
text file was supplied. A later concurrent raw-stream capture of the bare form
counted 127 nonempty stderr logical lines and zero stdout lines, so 153 must not
be reused as a raw native line count. Installed usage and
Microsoft's syntax expose `-i`, `-o`, and legacy-parser compatibility `-b`.
Installed usage also accepts the complete `HKEY_LOCAL_MACHINE`, `HKEY_USERS`,
`HKEY_CURRENT_USER`, and `USER:` prefixes, while PowerShell provider paths such
as `HKLM:\` remain a different syntax. The page now distinguishes all three
path models and replaces its `/y` registry backup with a no-clobber preflight.

Top-level `reg.exe /?` returned exit 0 and listed `FLAGS`, contradicting the
page's former claim to cover every subcommand. `reg.exe flags /?` was help-only
and showed query/set syntax for virtualization flags below local
`HKLM\Software`. It states that `SET` clears flags omitted from the command.
The installed example includes `/s` while the formal syntax line does not; the
page records that discrepancy without executing either `QUERY` or `SET`.
Microsoft's registry-virtualization contract confirms that `RECURSE_FLAG`
affects propagation to newly created descendants rather than retroactively
changing existing descendant keys.

A no-clobber SecEdit probe under the ordinary token targeted only a new system
temporary directory and `securitypolicy`. `/export` returned 740
(`ERROR_ELEVATION_REQUIRED`), created no INF, but left a two-byte log file.
The directory was resolved and verified to contain exactly that log; the file
and empty directory were deleted individually and no longer exist. The SecEdit
page now requires elevation for database/system queries, rejects existing
export/analyze paths, and treats access failure plus a partial log as distinct
from an empty policy or no side effect. No security setting or database was
changed, and the probe was not retried with a broader token.

## Windows FSUtil and mount help boundaries — 2026-08-12

Installed `fsutil.exe` top-level inventory returned 0 and listed 24 families.
Four were absent from the page and Microsoft's current FSUtil family index:
`bypassIo`, `dax`, `storageReserve`, and `trace`. Family-only help showed that
BypassIO has a query-only `state` verb, DAX queries file alignment,
StorageReserve separates `query`/`findByID` from mutating `repair`, and Trace
separates query/decode from start/stop. Microsoft's BypassIO driver guidance
independently documents the Windows 11 query, path scope, `/v` diagnostics,
